# Internal node seam

`packages/node/src/contract.ts` is the isolated `@reins/node/contract` export of a separately buildable node package. It contains a versioned semantic vocabulary for session open, prompt, steer, abort, pending resume, typed results and observations. It imports no server, Pi or browser modules; Oxlint restricts the contract's imports to `zod` and backend imports to the contract export. Future daemon implementation belongs elsewhere in `packages/node/src/`, not in this export. `deliveryPolicy()` classifies the existing commands for prospective transport: only session creation is `submit-work`; reopen, prompt, steer, abort and pending resume are `request-now` until explicitly redesigned. This is semantic policy, not a durable dispatcher or an offline guarantee. Future read-only workspace/git commands should use `request-now` and return unavailable when offline. `node-command-store.ts` owns SQLite outbox rows and transitions; `models/node-command-dispatcher.ts` checks delivery policy and resolves the session's current source. Session creation atomically stores the session and open command, then signals a dedicated dispatcher after commit. The signal carries no command payload; startup, node availability/reconnect wake, and a 30-second poll rescan SQLite. The dispatcher resolves the session's current source before claim and uses the internal Pi adapter to open it. Local browser/scripting creation still waits for opening before returning, but runtime creation is now asynchronous relative to persistence; queued unavailable sources cannot complete that wait until availability is restored. Future callers should use an explicit pending creation response rather than waiting indefinitely for an offline source. The outbox stores a session ID and operation, not a source. Without Pi-side durable admission keyed by command ID, dispatch failures and interrupted dispatch remain `unknown` rather than retried. Queued commands are retained when no adapter is available; the dispatcher polls for eligible commands. No external node adapter is implemented. Version 1 is **not** a network protocol: no handshake, framing, correlation, ordering, delivery guarantee or serialized runtime event payload is promised. Change schema meaning with a version bump; negotiate incompatible versions closed when transport exists.

`packages/backend/src/runtimes/node-execution.ts` resolves a session's persisted source and selects the internal execution adapter. Creation policy selects the default internal source, and `session-store.ts` requires an explicit source. Child sessions inherit their caller's source. `session-manager.ts` still constructs the in-process Pi runtime and owns local broadcast, lifecycle and storage. Unsupported nodes fail before local execution. Files, git, resource expansion and DB-backed tools remain local; this seam does not make the server repo-independent. Canonical Pi state remains in server SQLite and must be proven transportable before a daemon is added. See `docs/plans/node-architecture.md`.
