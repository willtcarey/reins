## Decisions

These were the plan's *Remote nodes: decided direction* (*Connection*, *Sources belong to the node*, *Versions*, *Bundle requirements*); the plan keeps only what still directs open work.

- **Connection:** the node dials a WebSocket at `/node-link` on the server's own HTTP server, `ws://` or `wss://` as the deployment provides (the private network carries transport security). It reads no cookies and is separate from the browser's `/ws`; the local Unix socket is unchanged, behind the same socket seam. The server speaks first (the challenge of ADR-023). The signature's origin comes from the upgrade request, forwarded headers first, with no configured public URL (ADR-024). A remote frame cap made chunked storage calls and a prompt-size bound prerequisites.
- **Sources belong to the node:** a remote node is the authority on its own paths. They are declared on the node, reported in its hello and attached to projects in Settings; the node refuses any call naming a checkout it does not declare. It verifies the path the server sends instead of resolving `sourceId → path` itself: the same guarantee without node-side state.
- **The server delivers the node's code** (as VS Code Remote installs its server): all Reins code on a node is one bundle built and hashed by the server, Bun the only other thing on the machine, the CLI and the node updating together. The hello carries the build ID and is answered `ready`, `update` or `error` (ADR-025). The session protocol stays lockstep and free to change: a node never runs code newer than its server, and an older one updates before it is served. Only the bootstrap surface (config, pairing request, challenge, hello envelope and reply, manifest, downloads, install script arguments, the `~/.reins` layout and launcher) must stay compatible, additively. An upgrade cuts off what is in flight on the node; the server resumes its runs (ADR-021).
- **Bundle requirements** (from the spike): a bundle-only entry registering Pi's OAuth flows and Bedrock module (computed `import()`s a bundle cannot follow); a stub for `@silvia-odwyer/photon-node` (its `__dirname` would point into the build checkout); guards against the repository path and unbundled externals; `--no-install`, `PI_PACKAGE_DIR`, `PI_OFFLINE` and `REINS_DOCS_DIR`; the faux-provider test hook removed by a define.

Where the build differs from that direction: the entry is `packages/cli/src/bundle/entry.ts` (not `packages/node`) and sets Pi's variables and `REINS_DOCS_DIR` itself, so the launcher is only the restart loop; `docs/features` is embedded in `reins.js` and unpacked beside it on first run, so one hash names code and docs; the install script execs `reins node setup` (pair, declare sources, start, wait) rather than `reins node pair`; the config's paths are `sources`, not `sourceRoots`; the bundle is not minified (readable stack traces; 12.3 MB plain, 2.36 MB gzipped).

## What was built

- **Bundle-safe node sources:** Pi extensions are never loaded (`noExtensions`); the environment prompt's REINS docs come from `REINS_DOCS_DIR` and name the developer docs only where they exist.
- **Credential lookups:** the node caches logged-out answers and the credential list until the next attach or `credentials.changed`: 241 `credentials.get` per runtime open became 43 on the first open after an attach and none after.
- **Chunked storage calls** (protocol 9): reads, commits and commit results over the link's storage chunk cross in slices of their JSON (`storage.readPart`, `storage.commitPart`), bounded per connection.
- **Remote transport:** JSON-RPC over WebSocket (`createWebSocketLink`; `nodes/node-link.ts` on the server, `remote-link.ts` on the node), accepted from `open` so the challenge is the first frame, owned by the handler load that upgraded it. A 16 MiB frame cap both ways; prompt content bounded to 8 MiB of JSON and the system prompt to 1 Mi characters, so an opening command fits. One redialer for both links, stopping on `NODE_REFUSED`. The dispatcher bounds deliveries per node (`MAX_SESSIONS_PER_NODE`), so a slow node cannot hold every slot. Settings' pairing step waits for the new node's first connection. `reins node run` runs a paired node in the foreground.
- **Node-owned sources:** `reins node source add|remove|list` (`node.json`'s `sources`), reported in the hello and recorded (`nodes.reported_sources`, migration `051`); every call naming a checkout checked against them as real paths (not abort); a running node watches its config and redials to re-report. Settings → Nodes lists each node's checkouts and attaches a declared one to a project (`POST /api/projects/:id/sources`). The local node declares none and serves any path.
- **The node bundle:** `reins.js` (the `reins` CLI and all of the node) built deterministically in its own `bun` process at each handler load; the build ID is its sha256.
- **Delivery and install:** `/nodes/install` (a POSIX sh script with the server URL, build ID, hash and Bun version filled in, failing in one line), `/nodes/manifest`, `/nodes/builds/<id>/reins.js`. The script fetches Bun's official release for the machine and the bundle, checks it, and execs `reins node setup <server> <code> [--source …]`. The `~/.reins` home (`bun`, `builds/`, `current`, `bin/reins`, `node.json`, `keys/`, `logs/`, `run/`); `reins node start|stop|status` with a status file trusted only while its pid's start time matches. Re-running the install command is safe, and with a fresh code repairs a node removed on the server.
- **Updates** (protocol 10): the hello carries `buildId`; a node on another build is told `update` (after authentication, before versions are compared), installs the bundle and if needed Bun, flips `current` and exits 75 for its launcher to start the new build. A failure leaves `current` as it was and is retried with backoff. Settings shows **updating…** and **old build**.

## Tests

Unit and route tests for each piece: `websocket-link.test.ts`, `node-link.test.ts` (endpoint, origin, caps), `remote-link.test.ts`, `node-storage.test.ts` (slices over a small cap, resent commits), `node-credentials.test.ts` and the node's `credentials.test.ts`, `node-command-dispatcher.test.ts` (per-node bound), `routes/nodes.test.ts`, `routes/sources.test.ts`, the CLI's `source`, `run`, `setup`, `control`, `install` and `update` tests, `node-bundle/build.test.ts` and `delivery.test.ts` (which runs the install script with `sh`), `node-builds.test.ts` (the server's update rule), and the Settings section and store tests. Process tests (`bun run test:process`): `remote-node.process-test.ts` (a paired node over the WebSocket, declared sources), `node-bundle.process-test.ts` (the bundle run outside the repository with no `node_modules`, a turn with a `bash` call) and `node-install.process-test.ts`, the acceptance test: the install command against a server serving its bundle installs, pairs and starts a node; its reported checkout is attached to a project and a session there completes a turn; the server restarts on another build and the node updates, restarts through its launcher and reconnects on the new build.

## Deferred

- Running the node as a background service (reboot persistence) and Windows.
- The local node on the bundle, and dropping the restart for protocol edits (the plan's *Local node on the bundle*): the local node still runs from source.
- Pruning old builds; temporary files an interrupted install leaves; the server caching Bun for machines without internet access; a sender for the `error` hello reply.
- Node-side stream pacing does nothing on Bun 1.3.9's client WebSocket (`bufferedAmount` is always 0).
- A long chunked commit is fenced, and its commit record checked, only at its last slice.
- Renaming a project does not update the node views that name it.
- Idle runtime eviction, multi-source checkout selection in the frontend, background process output, plugin-started nodes: still open items of the plan.

The plan's *Remote readiness* section was retired with this record: every server-local checkout operation already ran through the node (ADR-018), and its request table is node-contract.md *Checkout operations* and *Skills*.
