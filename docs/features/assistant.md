# Assistant

New conversations persist immediately; opening the local agent happens in the background. The session list shows queued/opening, source unavailable, or open failed separately from agent activity. A prompt submitted just after creation waits for a successful open before admission; an unavailable source rejects the prompt rather than silently saving it. The UI does not currently connect to external daemons. Failed commands notify the submitting client and leave the outbox after notification; delivery exceptions are reported as failures rather than blocking later inputs. If the node no longer has a session's execution data, the prompt fails with "This session's node data is missing. Start a new session." If a node's disk has been discarded, prompts to its old sessions fail with a visible error instead of leaving the composer streaming; server-side history remains readable, but the session cannot resume.

The assistant is your long-lived conversation for each project. It's always available at the top of the sidebar — just click it and start talking.

Use it to manage your project: ask questions about the codebase, brainstorm ideas, plan work, or have it create tasks for you. The composer accepts text, slash-skill suggestions, and image attachments from the + button, paste, or drag/drop onto the composer. On node-owned sessions, image bytes are verified and materialized in the node cache before Pi accepts the prompt; an unavailable or mismatched attachment fails admission rather than sending an image placeholder. Slash-skill invocations read skills from the session's bound source directory, even when the project's current directory differs. Locally sent messages spring from the composer into their normal conversation position; loaded or reconciled history does not replay the effect, and reduced-motion preferences disable it. Tapping send keeps the prompt focused when possible so the on-screen keyboard stays open; scrolling the conversation on mobile dismisses the keyboard. When creating a task, the assistant can also kick off a session on it immediately — the task is created and work begins in the background while you continue the conversation.

Messages can be copied as their original Markdown without adding permanent controls to the mobile transcript. Long-press a user or assistant message on mobile; the message content springs inward under your finger, while horizontally scrollable content such as a wide code block keeps the gesture for scrolling. On desktop, assistant messages have a corner copy icon, while both user and assistant messages support the context menu. Keyboard users can focus a message and press Shift+F10 (or the Context Menu key). User messages copy their raw text; assistant messages copy only raw text blocks, separated by blank lines, and omit thinking, tool calls, and tool results.

Implementation work preferably happens in a dedicated task session, but you can explicitly ask the assistant to implement here instead, including features or substantial changes. It should honor that request rather than require a task. Tasks are only created when you explicitly request one.

Unlike task sessions, which are scoped to a specific piece of work, the assistant sticks around. You keep talking to the same conversation over time. Long conversations open at their latest messages; scrolling to the top automatically loads previous history, or you can click "Load previous messages." Earlier messages are prepended without moving the message currently in view and remain available while the session is open. When you want a fresh start, click "New conversation" — the old one moves into a collapsible "Previous conversations" section.

The chat footer shows a compact context-window bar beside the session model. Its token count is the current prompt-context occupancy, not the session's cumulative token consumption. A new session starts at 0%; the bar uses the selected model's context window, warns as the automatic-compaction threshold approaches, and labels estimates with `~`. During a long-running response, Reins refreshes the occupancy about every 10 seconds while that conversation is visible in the foreground; background or non-chat views do not poll. During compaction Reins keeps showing the latest known durable occupancy; after compaction commits, it refreshes to an estimate until a later assistant response supplies an exact provider measurement. On narrow screens the bar remains visible; tap it to show the token detail. Desktop layouts show the token detail beside the bar.

If Reins stops while a session operation is in progress, reopening that conversation shows an interrupted-session notice with a Resume button. Resume continues the durable operation without adding a synthetic user message. Pending-operation state and the resume action use the session REST API; normal runtime progress continues over the existing WebSocket event stream.
