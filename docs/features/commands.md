# Commands

A message that starts with a command's name runs the command instead of being sent. This works in every conversation: the assistant and task sessions. Typing `/` at the start of a message suggests the commands, under a "Commands" heading, before the skills.

- **`/compact [instructions]`** summarizes the conversation so far, so that it takes less of the context window. Text after the command tells the summary what to keep, for example `/compact keep the API decisions and the open questions`. The conversation shows "Summarizing conversation…" while the summary is made, then the summary. While it runs, the session shows as running: Stop cancels it, and the conversation stays as it was. You cannot compact while the session is running, and a conversation with nothing new since its last summary has nothing to compact. If the summary fails, the error shows above the composer.
- **`/new [message]`** starts a new session in the same place as the session you are looking at. With no text after it, it opens the new session page with that session's project and task chosen. With text after it, it creates the session at once, with the text as its first message, and opens it: from the assistant, a new conversation; from a task session, a new session on that task; on the same machine and checkout as the session you typed it in. On the new session page, it uses the project and task chosen there.

A command is recognized only at the start of a message, as a whole word: `/compacting` and `please /compact` are sent as text. A `/word` that is not a command is sent as text, as before, and a skill of that name still expands (see [skills.md](skills.md)). At the start of a message, a command wins over a skill of the same name. If a command fails, its error shows above the composer and the text you typed stays, so you can try again. Attached images stay in the draft when a command runs.
